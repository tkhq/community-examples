## Overview

[Canopy](https://www.canopypay.io) is a crypto deposits API. Users deposit from a supported network and token, and Canopy settles to the destination your server specifies.

This guide shows how to fund an existing **Turnkey** Ethereum wallet with USDC on Base. Your server reads the Turnkey account, creates a Canopy payment intent for that address, and passes the intent ID to checkout. Your app can then read the USDC balance on Base and verify Canopy's signed settlement notifications.

The example uses one existing wallet and does not require a database. In an app with multiple users, select the wallet from the authenticated user's server-side account binding.

---

## Getting started

Follow the [Turnkey Quickstart guide](https://docs.turnkey.com/getting-started/quickstart). You need:

- An existing Next.js application with a Node.js server.
- A Turnkey organization, API key pair and Ethereum wallet account. The API key must be authorized to read that account.
- A Canopy account with secret and publishable keys, per-intent destinations enabled, and a Dynamic payout route to USDC on Base provisioned by Canopy. See [payout destinations](https://www.canopypay.io/concepts/destinations).
- A funded source wallet or exchange account. Use the network, token, deposit address and minimum shown by checkout.
- A registered HTTPS webhook endpoint and its signing secret if you want settlement notifications.

Set these values in `.env.local`:

```bash
# Turnkey API credentials
TURNKEY_API_PUBLIC_KEY=<your-api-public-key>
TURNKEY_API_PRIVATE_KEY=<your-api-private-key>

# Existing account for this example. These identifiers are not secrets.
TURNKEY_ORGANIZATION_ID=<organization-containing-the-wallet>
TURNKEY_WALLET_ID=<your-wallet-id>
TURNKEY_ACCOUNT_ADDRESS=<your-ethereum-account-address>

# Canopy credentials
CANOPY_SECRET_KEY=<your-canopy-secret-key>
CANOPY_WEBHOOK_SECRET=<your-webhook-signing-secret>
NEXT_PUBLIC_CANOPY_PUBLISHABLE_KEY=<your-canopy-publishable-key>
```

Keep the Turnkey private API key, Canopy secret key and webhook signing secret on the server. The Canopy publishable key is intended for client code. The Base chain ID and USDC contract are public constants defined below.

## Integration steps

### Read the Turnkey account and create a deposit

Create `lib/canopy-deposit.ts`. Read the configured account from Turnkey before creating the deposit. The browser only receives the intent ID, so it cannot select the payout address.

`BASE_USDC_ADDRESS` is the public USDC token contract listed in [Circle's contract addresses](https://developers.circle.com/stablecoins/usdc-contract-addresses). It is not a user wallet address or a secret.

```tsx
// lib/canopy-deposit.ts
import "server-only";
import { Turnkey } from "@turnkey/sdk-server";
import { getAddress, isAddress, zeroAddress } from "viem";

export const BASE_CHAIN_ID = 8453;
export const BASE_USDC_ADDRESS = "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913" as const;

function env(name: string): string {
  const value = process.env[name];
  if (!value || value.startsWith("<")) throw new Error(`${name} is not configured`);
  return value;
}

export async function resolveDestination() {
  const organizationId = env("TURNKEY_ORGANIZATION_ID");
  const walletId = env("TURNKEY_WALLET_ID");
  const address = getAddress(env("TURNKEY_ACCOUNT_ADDRESS"));
  const turnkey = new Turnkey({
    apiBaseUrl: "https://api.turnkey.com",
    defaultOrganizationId: organizationId,
    apiPublicKey: env("TURNKEY_API_PUBLIC_KEY"),
    apiPrivateKey: env("TURNKEY_API_PRIVATE_KEY"),
  }).apiClient();
  const { account } = await turnkey.getWalletAccount({ organizationId, walletId, address });
  if (
    account.organizationId !== organizationId || account.walletId !== walletId ||
    account.addressFormat !== "ADDRESS_FORMAT_ETHEREUM" || !isAddress(account.address) ||
    account.address.toLowerCase() === zeroAddress || account.address.toLowerCase() !== address.toLowerCase()
  ) throw new Error("Unexpected Turnkey account");
  return {
    payoutWallet: getAddress(account.address),
    payoutNamespace: "eip155" as const,
    payoutChainReference: String(BASE_CHAIN_ID),
    payoutTokenAddress: BASE_USDC_ADDRESS,
  };
}

async function requestDeposit(): Promise<{ intentId: string }> {
  const destination = await resolveDestination();
  const response = await fetch("https://www.canopypay.io/api/v1/intents", {
    method: "POST",
    headers: {
      Authorization: `Bearer ${env("CANOPY_SECRET_KEY")}`,
      "Canopy-Version": "2026-09-01",
      "Content-Type": "application/json",
    },
    body: JSON.stringify(destination),
    redirect: "error",
    cache: "no-store",
  });
  if (!response.ok) throw new Error(`Canopy create failed: HTTP ${response.status}`);
  const result: unknown = await response.json();
  if (!result || typeof result !== "object" || !("intentId" in result) ||
    typeof result.intentId !== "string" || !/^[0-9a-f]{32}$/.test(result.intentId)) {
    throw new Error("Unexpected Canopy intent response");
  }
  return { intentId: result.intentId };
}

// Share an in-flight request for this one-wallet, one-process example.
let pending: Promise<{ intentId: string }> | undefined;
export function createDeposit(): Promise<{ intentId: string }> {
  if (pending) return pending;
  const request = requestDeposit();
  pending = request;
  return request.finally(() => { if (pending === request) pending = undefined; });
}
```

Call `createDeposit()` from your application's authenticated server endpoint or server action, apply your existing authentication and CSRF protection, and pass the result to the client.

Canopy allows one active intent per merchant, namespace, chain, wallet and token. Creating again with the same destination and terms returns that active intent. This example always specifies the destination and uses a repeatable intent, so it does not need a local intent database. See [payment intents](https://www.canopypay.io/concepts/payment-intents).

### Open Canopy checkout

Pass the server's `intentId` to this client component. Checkout opens inside the button click and displays the supported source networks, tokens and deposit instructions.

```tsx
// components/CanopyDeposit.tsx
"use client";
import { useEffect, useRef, useState } from "react";
import { mount, type CanopyHandle } from "@canopypay/checkout-sdk";

export function CanopyDeposit({ intentId }: { intentId: string }) {
  const handle = useRef<CanopyHandle | null>(null);
  const [message, setMessage] = useState("");
  useEffect(() => () => { handle.current?.destroy(); handle.current = null; }, [intentId]);
  function openCheckout() {
    const merchant = process.env.NEXT_PUBLIC_CANOPY_PUBLISHABLE_KEY;
    if (!merchant) return setMessage("Checkout publishable key is not configured");
    const popup = window.open("", "canopy_checkout", "width=460,height=700");
    if (!popup) return setMessage("Allow popups to open checkout");
    handle.current?.destroy();
    handle.current = mount({
      target: "#canopy-checkout", intentId, merchant,
      canopyOrigin: "https://www.canopypay.io", surface: "popup",
      onEvent(event) {
        if (event.type === "error") setMessage(`Checkout error: ${String(event.code ?? "unknown")}`);
        if (event.type === "paid" || event.type === "deposit_detected") {
          setMessage("Deposit detected. Waiting for settlement.");
        }
      },
    });
    handle.current.openNow(popup);
  }
  return <>
    <button onClick={openCheckout}>Deposit</button>
    <div id="canopy-checkout" />
    <p role="status">{message}</p>
  </>;
}
```

The `paid` and `deposit_detected` browser events are advisory. Use them to update the interface; use server-side settlement evidence to fulfil a payment. See [SDK events](https://www.canopypay.io/sdk/events).

### Read the wallet's USDC balance

After settlement, read the same Turnkey account's USDC balance on Base. This reads the on-chain balance directly and does not create a separate application balance ledger.

```tsx
// lib/canopy-balance.ts
import "server-only";
import { createPublicClient, erc20Abi, formatUnits, http } from "viem";
import { base } from "viem/chains";
import { BASE_USDC_ADDRESS, resolveDestination } from "./canopy-deposit";

export async function readWalletBalance() {
  const { payoutWallet } = await resolveDestination();
  const client = createPublicClient({ chain: base, transport: http() });
  const units = await client.readContract({
    address: BASE_USDC_ADDRESS, abi: erc20Abi,
    functionName: "balanceOf", args: [payoutWallet],
  });
  return { units: units.toString(), balance: formatUnits(units, 6), symbol: "USDC" };
}
```

Refresh the balance after settlement or when checkout closes. A balance read can lag, and an aggregate wallet balance alone does not identify a particular deposit.

### Verify settlement notifications

Use this helper in your server's webhook handler. Give it the exact raw request body and headers. It verifies Canopy's Standard Webhooks signature before returning the payload.

```tsx
// lib/canopy-webhook.ts
import "server-only";
import { Webhook } from "standardwebhooks";

export function verifySettlementNotification(rawBody: string, headers: Headers): unknown {
  const secret = process.env.CANOPY_WEBHOOK_SECRET;
  if (!secret) throw new Error("Webhook secret is not configured");
  const plain: Record<string, string> = {};
  headers.forEach((value, key) => { plain[key.toLowerCase()] = value; });
  return new Webhook(secret).verify(rawBody, plain);
}
```

In a Next.js handler, obtain `rawBody` with `await request.text()`. Reject invalid signatures and only treat a verified payload with `state: "settled"` as a settlement notification. Keep `netUnits` and `feeUnits` as integer strings or `BigInt`.

For production payment fulfilment, save the intent-to-user mapping and verified deliveries durably before returning a successful webhook response. Deduplicate retries using `webhook-id`, match only intents your server created, and reconcile each unique transfer before crediting an application ledger. Use your existing database or durable queue for this; the guide does not require a particular database package. See [Canopy webhooks](https://www.canopypay.io/webhooks).

- Verify signed settlement notifications and identify the persistence needed for production fulfilment.
